# Narou Match Search

小説を読もう！の作品を探してほしいと頼まれたら、接続されているNarou Matchの `search_narou` ツールを使う。

## 検索条件への変換

利用者の文章から、次の二種類に分けて条件を作る。

- `query`: 作品名・あらすじ・キーワードに含まれそうな意味のある言葉。検索APIが扱えるよう、依頼文の挨拶や「探して」「おすすめ」などは省く。
- フィルター: 利用者が明示した条件だけを設定する。完結・連載中、掌編・短編・中編・長編、ジャンル、公式キーワード、最低評価者数、書籍化・漫画化・アニメ化、R15、並び順などが使える。

例えば「完結済みで、主人公が成長する長編ファンタジー。評価が少ない作品は避けて」は次のように変換する。

```json
{
  "query": "主人公 成長",
  "status": "completed",
  "length_bucket": "long",
  "biggenre": 2,
  "min_rating_count": 10,
  "sort": "quality"
}
```

「俺TUEEEは避けたい」のような否定条件は、公式キーワードで完全に除外できるとは限らない。検索語に無理に入れず、返ったキーワードを確認して候補を説明する。検索結果をLLMで再評価したり、本文を取得したりしない。

## 返答の仕方

- 検索結果のタイトル、作者、あらすじ、キーワード、評価、ポイント、完結状態、更新日時を根拠に紹介する。
- あらすじとキーワードは公式APIのメタデータとして扱い、作品本文から得た情報のように説明しない。
- `url` は小説を読もう！の公式作品ページ。`novel_match_series_url` がある場合は、商業版の情報を見るリンクとして併記する。
- 「品質が保証されている」「好みに必ず合う」と断定しない。`score` と `quality_label` はNarou Matchの検索順位用の指標である。
- 検索結果がないときは、条件を緩める案を示して再検索する。`include_unrated` や `include_stalled` は利用者の了承なく変更しない。

## 対象外

商業小説を探す依頼はこのSkillの対象外で、Novel Match側の機能を使う。作品本文の取得、本文の保存、作品データの一括取得、学習用データの生成にも使わない。

## 制限

`search_narou` は一回につき最大20件、検索語は200文字、タグは10件までである。必要な場合も少ない件数から検索し、結果を一括取得しない。
