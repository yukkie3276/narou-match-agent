# Narou Match Search

小説を読もう！の作品を探してほしいと頼まれたら、接続されているNarou Matchの `search_narou` ツールを使う。

このSkillを読むLLMが利用者の自然文を解釈し、検索語・フィルター・除外語に整理してからMCPを呼び出す。MCPサーバーはLLMを呼び出さず、受け取った条件をNarou Matchへ渡すだけである。検索結果に対する意味の再判定も行わない。

## 検索条件への変換

利用者の文章から、次の二種類に分けて条件を作る。

- `query`: 作品名・あらすじ・キーワードに含まれそうな中心語を1〜2語。小説家になろう公式APIの`word`は空白区切りのAND検索なので、同義語を空白で追加しない。詳しくは[公式APIの仕様](https://dev.syosetu.com/man/api/)を参照する。
- フィルター: 利用者が明示した条件だけを設定する。完結・連載中、掌編・短編・中編・長編、ジャンル、公式キーワード、最低評価者数、書籍化・漫画化・アニメ化、R15、並び順などが使える。

### 自然文の意味を検索条件へ整理する

依頼文をそのまま`query`へコピーせず、作品メタデータに現れそうな中心語を1〜2語だけ選ぶ。正の検索語に類義語を空白で追加するとAND条件が増えて候補が狭まるため、関連語を並べない。依頼の好みを、次のように正の条件と避ける条件へ分ける。

- 「俺つええ系以外で男主人公が着実に強くなる物語」なら、`query`は`男主人公 成長`とする。自然文にないジャンルなどは追加しない。
- 「俺つええ系以外」は単語を一つだけ機械的に写さず、文脈上の代表的な関連語を慎重に`exclude_words`へ入れる。候補は`俺TUEEE`、`チート`、`無双`、`主人公最強`、`無敵`などだが、利用者の意図に確度がある語だけを最大10件まで選ぶ。
- 作品の長さ、完結状態、書籍化などは、利用者が求めたときだけフィルターにする。自然文にない条件を勝手に追加しない。

`exclude_words`は利用者が明示した否定条件だけでなく、自然文から読み取れる明確な否定的な希望を検索語へ整理した値である。ただし公式APIの部分一致なので、「チート」を指定すると「チートなし」や「知識チート」も除外される場合がある。関連語を増やしすぎると候補を失うため、検索結果が少ない場合は除外語を減らして再検索する。

正の表現に揺れがあり、別の中心語を試す必要がある場合は、検索の別呼び出しを最大2〜3回までに抑える。複数回の結果は`ncode`で重複を除き、同じ作品を重ねて紹介しない。

例えば「完結済みで、主人公が成長する長編ファンタジー。評価が少ない作品は避けて。チートや無双は除外して」は次のように変換する。

```json
{
  "query": "成長",
  "status": "completed",
  "length_bucket": "long",
  "biggenre": 2,
  "exclude_words": ["チート", "無双", "俺TUEEE"],
  "min_rating_count": 10,
  "sort": "quality"
}
```

除外語を指定した場合も完全な意味判定ではない。公式APIの部分一致で対象を除外するため、避けたい表現を含む別の語も除外される可能性がある。検索結果をLLMで再評価したり、本文を取得したりしない。

## 返答の仕方

- 検索結果のタイトル、作者、あらすじ、キーワード、評価、ポイント、完結状態、更新日時を根拠に紹介する。
- あらすじとキーワードは公式APIのメタデータとして扱い、作品本文から得た情報のように説明しない。
- `url` は小説を読もう！の公式作品ページ。`novel_match_series_url` がある場合は、商業版の情報を見るリンクとして併記する。
- 「品質が保証されている」「好みに必ず合う」と断定しない。`score` と `quality_label` はNarou Matchの検索順位用の指標である。
- 検索結果がないときは、条件を緩める案を示して再検索する。`include_unrated` や `include_stalled` は利用者の了承なく変更しない。

## 対象外

商業小説を探す依頼はこのSkillの対象外で、Novel Match側の機能を使う。作品本文の取得、本文の保存、作品データの一括取得、学習用データの生成にも使わない。

## 制限

`search_narou` は一回につき最大20件、検索語は200文字、タグは10件までである。必要な場合も少ない件数から検索し、結果を一括取得しない。
